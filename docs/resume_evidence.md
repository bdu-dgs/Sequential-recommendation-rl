# Resume evidence

Each number in the resume bullets is traced to a report table, the run directories that produced it, and a
reproduce command. Policy numbers are **simulated returns** (KuaiRecFO-v1), not real-user metrics. Write them

## Entry

**Support-Aware Offline-to-Online RL for Sequential Recommendation** | Python, PyTorch, Offline RL (CQL, BCQ,
Cal-QL), DQN, Contextual Bandits, Off-Policy Evaluation, Pandas

### Version A — the bullets currently on the resume (all still accurate)
1. Audited KuaiRec log and built temporal and unseen-user holdouts; verified propensities were unavailable.
2. Designed a simulator separating logged rewards from synthetic transitions, with known-propensity logs for
   IPS/DR evaluation.
3. Built a recommendation MDP with dynamic-programming optimum to check DQN updates and compare offline RL
   methods.

### Version B — quantified, recommended
1. Audited the 12.5M-interaction KuaiRec log: removed 0.97M duplicate rows (7.7%), built temporal and
   unseen-user holdouts, and confirmed propensities were unavailable. A GRU response model reached AUC 0.651
   on unseen users, against 0.617 for item mean.
2. Built a simulator with real fully-observed rewards, synthetic transitions, and known-propensity logs.
   Offline DQN chose unsupported items 66% of the time, for a simulated return of 21.6 vs 44.6 for CQL. IPS
   error rose from 1% to 82% as off-support mass grew.
3. Studied offline-to-online fine-tuning over 217 runs and 5 seeds. Removing conservatism caused a 34.7-point
   drop, which Cal-QL limited to 0.3. My support-weighted CQL lost to a strength-matched control (−10.0 vs
   −0.9), which I traced to +38 Q-overestimation on mid-support items.

Shorter variant of B3, if space is tight: "Fine-tuning study (217 runs, 5 seeds): naive fine-tuning dropped
34.7 points vs 0.3 for Cal-QL; diagnosed why a support-weighted CQL variant underperformed (+38 Q
overestimation on thinly logged items)."

## Wording rules
- Write "simulated return", never "engagement", "watch time", or "CTR uplift". No real users were involved.
- "Known-propensity logs" means *our own* simulated logging policy, never KuaiRec's.
- The support-weighted method is a negative result. Do not describe it as an improvement.
